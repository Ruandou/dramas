## 1. 什么走 Git，什么不走

| 走 Git（拉取/合并/PR） | 不走 Git（各自本地或网盘） |
|------------------------|----------------------------|
| `分集剧本/*.md`、`EP##_segments.yaml`、`EP##_shots.yaml` | `assets/generated/**/*.mp4`（`.gitignore`） |
| `角色卡.md`、`制片规范.md`、`docs/` | `configs/seedance_requests/`（体积大） |
| `assets/looks/`、`assets/scenes/` 定妆/场景图 | 可选：大体积 `keyframes/` 批量图 |
| `assets/generated/EP##/tasks.json` | 集级 `EP##_full.mp4`（可由一人本地 concat 后外发审片） |

**结论**：同事之间靠 **Git 对齐「怎么拍」**；**成片 MP4 靠网盘/NAS/飞书盘** 传审，不要指望 `git push` 传视频。

## 2. 推荐分工

| 角色 | 负责 | 主要改动的文件 |
|------|------|----------------|
| 编剧/导演 | 剧情、对白、分镜表 | `分集剧本/EP##_*.md`、`EP##_shots.yaml` |
| 制片/统筹 | 段落切分、时长、ID | `EP##_segments.yaml`、`制片规范.md` |
| 美术 | 定妆、场景、道具参考 | `assets/looks/`、`assets/scenes/`、`assets/props/` |
| 生成执行 | 调 API、下载段落 | 本地 `generated/EP##/EP01-SEG*.mp4`、`tasks.json` |
| 审片 | 验收、问题单 | `trial_notes.md`、Issue/飞书文档 |

同一人可兼多角；**同一集建议指定一位「集负责人」** 合并 yaml、拍板 concat 顺序。

## 3. 防冲突：按集 / 按段认领

在 `工作计划.md` 或飞书表维护（示例）：

| 集 | 段 | 负责人 | 状态 |
|----|-----|--------|------|
| EP01 | SEG01a–02 | 张三 | 已下载 |
| EP01 | SEG05 | 李四 | 待重跑 |
| EP02 | 全集 segments 草案 | 王五 | 编写中 |

**规则**：

- **不要两人同时改** 同一 `EP##_segments.yaml`；改前 `git pull`，改完 push/PR。  
- **段落生成**可并行：不同 `segment_id` 互不覆盖（文件名不同）。  
- **集负责人** 在所有人段落就绪后执行一次 `ffmpeg_concat_episode.sh`。

## 4. Git 协作流程（日常）

```bash
git pull origin main
cd darams/天工开物
export DRAMA_PROJECT_ROOT=$PWD
# 改 yaml / 文档 → 提交 PR
python3 script/storyboard_submit_segments.py EP01 --check-only
```

1. 功能分支：`feat/ep01-seg05-hammer-fix`  
2. PR 只含 **yaml / md / tasks.json / 定妆图**（不含 mp4）  
3. Review 通过后 merge；生成同事再 `git pull` 按新 prompt 重跑段  

`tasks.json` 冲突时：两人各跑不同 segment，合并后应是 **多条 task 记录**；若同一 `task_id` 冲突，保留最新一次提交说明（commit message 写清 segment）。

## 5. 一键拉同事成片（推荐）

同事 **push `tasks.json`** 后，你本地执行（24h 内有效）：

```bash
cd darams/天工开物
export ARK_API_KEY=…
./tgkw pull EP01 --concat
```

或在 Cursor 直接说：**`ark_drama_pull`**（`episode=EP01`, `concat=true`）— 用已配置的 volc-ark MCP Key，**不必再 export**。

等价于：`git pull` → 按 `tasks.json` 下载缺段 → 可选拼 `EP##_full.mp4`。

## 6. 成片怎么给同事看（网盘备选）

任选一种团队习惯（写进群公告即可）：

| 方式 | 适用 |
|------|------|
| 网盘/NAS 目录 `天工开物/审片/EP01/` | 集负责人上传 `EP01_full.mp4` + 有问题段落单独传 |
| 只传有问题段 | 省流量；审片人本地 concat 或只看单段 |
| 屏幕录制 + 时间码 | 临时讨论，不作为母版 |

**不要**把 MP4 提交进 Git（仓库体积、且无 LFS 配置）。

## 7. 密钥与环境（每人本地）

| 项 | 做法 |
|----|------|
| `ARK_API_KEY` | 每人自己的方舟 Key，或团队共用 Key 只放 **本地** `.cursor/mcp.json`（**勿提交**） |
| `DRAMA_PROJECT_ROOT` | 各自机器上指向克隆目录下的 `darams/天工开物`（路径可不同，用绝对路径即可） |
| 扣费 | 生成前在群里报「跑 EP01 SEG05」；避免两人重复 submit 同一段 |

`.cursor/mcp.json.example` 可复制为 `mcp.json` 并填 Key + `DRAMA_PROJECT_ROOT`。

## 8. 并行生成同一集

可以并行：

```bash
# 张三
python3 script/storyboard_submit_segments.py EP01 --segment EP01-SEG04a --submit --wait --download
# 李四
python3 script/storyboard_submit_segments.py EP01 --segment EP01-SEG05 --submit --wait --download
```

完成后：

1. 各自把 `EP01-SEG04a.mp4` 等放到 **约定网盘路径**，或集负责人 **U 盘/内网拷贝** 到同一台机器的 `assets/generated/EP01/`  
2. 集负责人 `ls -lh` 验收 → `bash script/ffmpeg_concat_episode.sh EP01`  
3. 把更新后的 `tasks.json`（含两段 task_id）**提交 Git**

`--skip-existing` 适合集负责人扫尾补跑缺段，不适合两人对同一段各跑一遍（浪费费用）。
