## 1. 什么走 Git，什么不走

| 走 Git（拉取 / 合并 / PR） | 不走 Git（各自本地或网盘） |
|--------------------------|--------------------------|
| `剧本/EP##/*.md`、`EP##_segments.yaml`、`EP##_shots.yaml` | `assets/generated/**/*.mp4`（`.gitignore`） |
| `角色卡.md`、`制片规范.md`、`docs/` | `assets/keyframes/EP##/`（体积大时可不提交） |
| `assets/looks/`、`assets/scenes/` 定妆 / 场景图 | `configs/seedance_requests/`（体积大） |
| `assets/generated/EP##/tasks.json` | 集级 `EP##_full.mp4`（由集负责人本地 concat 后外传审片） |

**结论**：同事之间靠 **Git 对齐「怎么拍」**；**成片 MP4 靠网盘 / NAS / 飞书盘** 传审，不要靠 `git push` 传视频。

## 2. 推荐分工

| 角色 | 负责 | 主要改动文件 |
|------|------|------------|
| 编剧 / 导演 | 剧情、对白、分镜表 | `剧本/EP##_*.md`、`EP##_shots.yaml` |
| 制片 / 统筹 | 段落切分、时长、ID | `EP##_segments.yaml`、`制片规范.md` |
| 美术 | 定妆、场景、道具参考 | `assets/looks/`、`assets/scenes/`、`assets/props/` |
| 生成执行 | 调 API、下载段落 | 本地 `generated/EP##/EP##-SEG*.mp4`、`tasks.json` |
| 年代审片 | 验收 1995 穿帮、问题单 | `trial_notes.md`、Issue / 飞书文档 |

同一人可兼多角；**同一集建议指定一位「集负责人」** 合并 yaml、拍板 concat 顺序。

## 3. 防冲突：按集 / 按段认领

在 `工作计划.md` 或飞书表维护（示例）：

| 集 | 段 | 负责人 | 状态 |
|----|----|--------|------|
| EP01 | SEG01–SEG03 | 张三 | 已下载 |
| EP01 | SEG04–SEG06 | 李四 | 生成中 |
| EP02 | 全集 segments 草案 | 王五 | 编写中 |

**规则**：

- **不要两人同时改**同一 `EP##_segments.yaml`；改前 `git pull`，改完 push / PR。
- **段落生成**可并行：不同 `segment_id` 写入不同 MP4 文件，互不覆盖。
- **集负责人**在所有人段落就绪后执行一次 `ffmpeg_concat_episode.sh`。

## 4. Git 协作流程（日常）

```bash
# 开始工作前
git pull origin main
cd darams/超雄重生1995
export DRAMA_PROJECT_ROOT=$PWD

# 导出分镜 YAML（改完 剧本/EP##/*.md 后）
python3 script/storyboard_to_seedance.py EP01

# 年代合规校验（提交前必过）
python3 script/validate_era.py EP01

# 确认无问题后提交
git add 剧本/EP01/ assets/looks/ assets/scenes/
git commit -m "feat(EP01): 更新分镜 YAML + 补 CHAR-001 定妆图"
```

**分支策略**：

1. 功能分支：`feat/ep01-seg03-chase-fix`
2. PR 只含 **yaml / md / tasks.json / 定妆图**（不含 mp4）
3. Review 通过后 merge；生成同事再 `git pull` 按新 prompt 重跑段

`tasks.json` 冲突时：保留所有人的 task 记录（多条），若同一 `task_id` 冲突保留最新提交，commit message 写清 segment_id。

## 5. 一键拉同事段落

同事 **push `tasks.json`** 后，你本地执行（**24h 内**，直链过期则需重下）：

```bash
cd darams/超雄重生1995
export ARK_API_KEY=…
./script/pull_episode.sh EP01
```

或在 Cursor 直接说：**`ark_drama_pull`**（`episode=EP01`，`concat=true`）—— 用已配置的 volc-ark MCP Key，不必再 export。

等价流程：`git pull` → 按 `tasks.json` 下载缺段 → 可选拼 `EP##_full.mp4`。

> ⚠️ 视频直链有效期约 **24 小时**。同事 push tasks.json 后请及时拉取，过期需重新下载或重跑段落。

## 6. 成片怎么给同事看

任选一种团队习惯（写进群公告即可）：

| 方式 | 适用 |
|------|------|
| 网盘 / NAS `超雄重生1995/审片/EP##/` | 集负责人上传 `EP##_full.mp4` + 有问题段落单独传 |
| 只传有问题段 | 省流量；审片人本地 concat 或只看单段 |
| 屏幕录制 + 时间码 | 临时讨论，不作为母版 |

**不要**把 MP4 提交进 Git（仓库体积膨胀，且无 LFS 配置）。

## 7. 密钥与环境（每人本地）

| 项 | 做法 |
|----|------|
| `ARK_API_KEY` | 每人自己的方舟 Key，或团队共用 Key 只放**本地** `.cursor/mcp.json`（**勿提交**） |
| `DRAMA_PROJECT_ROOT` | 各自机器上指向 `darams/超雄重生1995`（路径可不同，用绝对路径） |
| 扣费 | 生成前在群里报「跑 EP01 SEG03」；避免两人重复 submit 同一段 |

`.cursor/mcp.json.example` 可复制为 `mcp.json` 并填 Key + `DRAMA_PROJECT_ROOT`：

```json
"volc-ark": {
  "env": {
    "ARK_API_KEY": "your_key_here",
    "DRAMA_PROJECT_ROOT": "/Users/xxx/Movies/dramas/darams/超雄重生1995"
  }
}
```

## 8. 并行生成同一集

可以并行：

```bash
# 张三：生成 EP01 SEG01–SEG03
python3 script/storyboard_submit_segments.py EP01 --segment EP01-SEG01 --submit --wait --download
python3 script/storyboard_submit_segments.py EP01 --segment EP01-SEG02 --submit --wait --download

# 李四：生成 EP01 SEG04–SEG06（不同 segment_id，互不覆盖）
python3 script/storyboard_submit_segments.py EP01 --segment EP01-SEG04 --submit --wait --download
```

完成后：

1. 各自把 `EP##-SEG*.mp4` 放到约定网盘路径，或集负责人内网拷贝
2. 集负责人 `ls -lh assets/generated/EP01/` 验收体积（正常为数 MB；数 KB = 异常）
3. `bash script/ffmpeg_concat_episode.sh EP01`
4. 把更新后的 `tasks.json`（含所有人 task_id）**提交 Git**

## 9. ID 纪律（核心规则）

**技术文件中禁止写明文人名，必须用 ID。**

| 正确 | 错误 |
|------|------|
| `CHAR-001` | 陆峥 |
| `SCENE-003` | 城南派出所 |
| `CHAR-001-L01` | 陆峥日常形象 |

ID 与明文的对应关系只维护在 `角色卡.md` / `资产/场景卡片.md` 中。分镜、YAML、脚本仅做引用，不写中文人名或地点。

## 10. 年代合规检查（1995）

**提交前 checklist**：

- [ ] `segments.yaml` 已 merge 到 main，`--check-only` 通过
- [ ] `validate_era.py` 无 error（1995 年代 Negative 关键词检查）
- [ ] 认领 segment，避免重复 submit 浪费费用
- [ ] 下载后单段体积正常（`ls -lh`，数 MB 级）
- [ ] 审片：无智能手机 / 平板 / LED 广告屏 / 2000 后车型穿帮
- [ ] 问题记入 `trial_notes.md` 或 Issue（镜号 + segment_id + 现象）
- [ ] 审片通过后再对外发 `EP##_full.mp4`

## 11. 阻塞问题沟通协议

遇到以下情况**立即在群里同步**，不要自己扛：

| 情况 | 处理 |
|------|------|
| API 报错 / task 失败 | 贴 task_id + 错误信息 |
| 素材穿帮（严重年代问题） | 截图 + segment_id，通知美术重出定妆图 |
| 直链过期（24h） | 通知集负责人重跑或重下 |
| yaml 合并冲突 | 保留两人所有 segment，不丢 task_id |
| 费用异常（重复生成） | 立即暂停，核对认领表 |
