## 一、ID 命名规则

| 类型     | 格式                              | 示例              | 用途                             |
| -------- | --------------------------------- | ----------------- | -------------------------------- |
| **角色** | `CHAR-###`                        | `CHAR-001`        | 对白、关系、选角（谁）           |
| **形象** | `CHAR-###-L##`                    | `CHAR-001-L01`    | 出图、妆造、分镜视觉（长什么样） |
| 群演     | `CHAR-GRP-##` / `CHAR-GRP-##-L01` | `CHAR-GRP-01-L01` | 通用脸型一套即可                 |
| 场景     | `SCENE-###`                       | `SCENE-001`       | 布景                             |
| 分集     | `EP##`                            | `EP01`            | 分集文件                         |
| 镜头     | `EP##-S##`                        | `EP01-S01`        | 集数-镜号                        |
| 段落     | `EP##-SEG##`                      | `EP01-SEG01`      | AI 生成单位                      |
| 道具     | `PROP-###`                        | `PROP-001`        | 关键道具                         |

- 编号**只增不删**；弃用标 `deprecated: true`。
- 新建角色：先 `资产/角色索引.md`，再建 **`L01` 基础形象**于 `资产/形象索引.md` + `角色卡.md`。
- 新建换装/阶段：**只加 `L02+` 衍生形象**，并写明 `based_on: CHAR-xxx-L01`。

### 1.1 形象 ID 与基础 / 衍生

| 后缀     | 名称     | 要求                                                                                |
| -------- | -------- | ----------------------------------------------------------------------------------- |
| **L01**  | 基础形象 | 完整定妆 Prompt（脸、体型、发式、默认服装）；全剧面部一致性的**唯一锚点**           |
| **L02+** | 衍生形象 | **必须** `based_on` 本角色 `L01`；Prompt 只写差异，并含 `same face as CHAR-xxx-L01` |

**出图流程**：定稿 `L01` 参考图 → 衍生形象用图生图 / 角色一致性模型 → 禁止跳过 L01 直接生成 L02。

**本剧常见衍生场景**：

| 角色     | L01（基础）           | L02+（衍生示例）                                |
| -------- | --------------------- | ----------------------------------------------- |
| 周小凡   | 日常灰色西装          | L02 休闲装、L03 带电弧特效西装                  |
| 雷震子   | 白色古装束冠          | L02 古装+现代元素（奶茶杯）、L03 执法长袍       |

| 林总监   | 深色西装              | —                                               |
| 玄诚子   | 灰色道袍              | —                                               |

## 二、视觉风格锚点 (Visual Style Anchor)

### 2.1 渲染风格

- **风格**：现代都市写实 + 仙侠光效叠加
- **写实度**：8/10（偏写实，仙侠元素通过光效/粒子实现，不做卡通/插画）
- **色调体系**：
  - 都市线：暖色自然光（办公室荧光灯、便利店冷白光、住宅暖黄灯）
  - 仙侠线：高对比冷色光效（蓝色电弧、紫色法阵、金色灵气）
- **笔触/质感**：写实照片级渲染，皮肤纹理可见，材质细节清晰

### 2.2 题材视觉标记

| 类型   | 标记元素                                                       |
| ------ | -------------------------------------------------------------- |
| 都市   | 格子间/荧光灯/玻璃幕墙/自动门/电子屏幕/外卖包装              |
| 仙侠   | 雷电光效/法阵蓝光/道袍/束冠/灵气粒子/云海/仙鹤              |

### 2.3 竖屏构图约束

- 画面比例：9:16（竖屏优先）
- 双人对话：优先上下或对角线构图，避免并排
- 办公室场景：利用格子间纵向纵深
- 仙侠场景：利用仰拍/俯拍强调纵深

## 三、分段与镜头规范

### 3.1 核心参数

| 参数             | 规格                        |
| ---------------- | --------------------------- |
| 单集总时长       | ≥ 140s 且 ≤ 200s（理想 150-180s） |
| Segment 时长     | 4-12s（理想 8-10s）         |
| Segment 镜头数   | 1-3 镜                      |
| 每集 Segment 数  | 12-15 段                    |
| 每集镜头数       | 15-30 个 Seedance 有效镜头  |
| 每集场景数       | 4-7 个                      |
| 对白密度         | ≥ 50 行，≥ 20 行/分钟       |
| 静音段           | ≤ 1 段/集                   |
| 说话人/段        | ≤ 2 人                      |

### 3.2 分段规则

- 不得在对话中间切断
- 不得跨场景（每个 segment 内所有镜头属同一 SCENE-###）
- 单段至少 3 行台词/独白；主角独处必须有内心独白
- 角色换装 → 切段后作为新 segment

### 3.3 Seedance 模型配置

```yaml
seedance_defaults:
  model: doubao-seedance-2-0-fast
  ratio: "9:16"
  resolution: 720p
  duration_sec: "8-10"
  generate_audio: true
```

## 四、Prompt 后缀与 Negative Prompt

### 4.1 prompt_suffix

```
禁止画面中出现任何文字或字幕。都市写实风格，仙侠光效叠加，偏写实不做卡通插画，竖屏9比16。
```

### 4.2 negative_prompt

```
anime, cartoon, illustration, manga, chibi, low quality, blurry, deformed,
text, subtitle, watermark, logo, logo mark, QR code, barcode,
modern military, police uniform, gun, weapon (except ancient Chinese sword),
blood, gore, horror, nsfw,
medieval European, western fantasy, steampunk,
multiple limbs, extra fingers, missing fingers, distorted face
```

### 4.3 年代/题材禁忌

- **禁止**出现：现代军事/警用装备、枪支（雷震子的剑除外）、血腥暴力
- **仙侠场景禁止**：西方魔幻元素（魔法杖/精灵/中世纪铠甲）
- **都市场景禁止**：古装人物与完全现代环境不合理的违和感（需通过光效过渡）
- **文字渲染**：无文字场景 negative 必须含 `no text, no characters, no signs with text`；有文字场景需精确引用中文字符

## 六、TTS / 配音方向

### 6.1 配音风格总纲

- **都市线**：现代职场口语，语速偏快，自然不做作
- **仙侠线**：古风腔调，措辞古雅但不过度夸张（避免"古装剧腔"）
- **喜剧线**：语速灵活，配合场景反差做节奏变化

### 6.2 角色声音方向

## 八、工作流顺序（修改层级）

改台词、场次、字幕/旁白策略时**严格按层向下**，**禁止**先改 yaml 再回头补剧本。

| 顺序 | 层           | 文件                     | 写什么                                                    |
| :--: | ------------ | ------------------------ | --------------------------------------------------------- |
| **1** | **主剧本**   | 短剧剧本_雷劫劈错人了_36集.md | 集纲、每场剧情、对白要点、钩子                          |
| **2** | **分集剧本** | 剧本/EP##/EP##_*.md       | 可拍分镜表：shot_id、画面、对白/备注、CHAR/SCENE/形象、时长/模式/运镜 |
| **3** | **机器可读** | 同目录 EP##_shots.yaml    | 从分集 md 导出，勿手改 yaml 当源                         |
| **4** | **段落 API** | 同目录 EP##_segments.yaml | 按 md 镜号合并为 segment                                  |
| **5** | **其它**     | 声音卡、assets/           | 仅在前几步定稿后随需更新                                  |

**单集真相源**：拍什么、说什么 → **`剧本/EP##_*.md`**

## 十、引用图片提交策略

### TOS 优先，base64 兜底

| 优先级 | 方式           | 适用场景                           |
| ------ | -------------- | ---------------------------------- |
| 1      | TOS URL        | 已上传至 TOS 的图片，请求体积最小  |
| 2      | base64 data URI | TOS 未上传时兜底，≤3 张/段        |

上传图片至 TOS 后，在 `assets/looks/` 或 `assets/scenes/` 同目录下维护 `cdn_urls.json`：
```json
{
  "CHAR-001-L01": {
    "local": "CHAR-001-L01.png",
    "tos_url": "https://drama-reference-images.tos-cn-beijing.volces.com/雷劫劈错人了/looks/CHAR-001-L01.png"
  }
}
```

- **TOS 模式**：允许 4-6 张引用图片/段
- **base64 模式**：保守限制 ≤3 张引用图片/段
- 本地 PNG 文件始终保留作为最终备份

## 十一、Seedance 可拍性高风险镜头规避

| 高风险类型               | 替代方案                       |
| ------------------------ | ------------------------------ |
| >3 人同框交互            | 拆成反打镜头或分组             |
| 精细手指动作             | 改为特写道具 + 画外音          |
| 快速运镜 + 角色大幅运动  | 固定机位拍动作                 |
| 画面内需辨认的文字       | 画外音读出 + 模糊特写          |
| 对白时嘴部极近特写       | 改为中近景或侧面角度           |
| 单段内角色换装           | 切段后作为新 segment           |
| 复杂打斗（>2 人格斗）   | 拆为连续单人动作段             |
| 雷电/法阵特效            | 用光效粒子描述，不要求精确物理模拟 |
