## 一、ID 命名规则

所有资产必须使用统一编码，**只增不删**；弃用标 `deprecated: true`。

| 类型     | 格式                              | 示例              | 用途                             |
| -------- | --------------------------------- | ----------------- | -------------------------------- |
| **角色** | `CHAR-###`                        | `CHAR-001`        | 对白、关系、选角（谁）           |
| **形象** | `CHAR-###-L##`                    | `CHAR-001-L01`    | 出图、妆造、分镜视觉（长什么样） |
| 群演     | `CHAR-GRP-##` / `CHAR-GRP-##-L01` | `CHAR-GRP-01-L01` | 通用脸型一套即可                 |
| 场景     | `SCENE-###`                       | `SCENE-002`       | 布景                             |
| 道具     | `PROP-###`                        | `PROP-001`        | 关键道具                         |
| 分集     | `EP##`                            | `EP01`            | 分集文件                         |
| 镜头     | `EP##-S##`                        | `EP01-S03`        | 集数-镜号                        |

### ID 分配规则

- 编号**连续、不跳号**
- 新建角色：先在 `资产/角色索引.md` 登记 `CHAR-###`，再由 character-designer（Stage 3a）建 `L01` 基础形象
- 新建换装/阶段形象：**只加 `L02+` 衍生形象**，并写明 `based_on: CHAR-xxx-L01`
- 群演分级：有名字+跨segment出现→独立CHAR-###；纯背景无台词→CHAR-GRP

### 形象层级结构定义

| 后缀     | 名称     | 说明                                           |
| -------- | -------- | ---------------------------------------------- |
| **L01**  | 基础形象 | 全剧面部一致性的**唯一锚点**                   |
| **L02+** | 衍生形象 | 必须 `based_on` 本角色 `L01`；禁止跳过 L01    |

## 四、工作流顺序（必读 · 防不同步）

制片规范确立后，所有内容修改**严格按层向下**：

| 顺序  | 层           | 文件                     | 写什么                                              |
| :---: | ------------ | ------------------------ | --------------------------------------------------- |
| **1** | **主剧本**   | `短剧剧本_前任的弟弟是我的租客_36集.md` | 集纲、每场剧情、对白要点、钩子        |
| **2** | **分集剧本** | `剧本/EP##/EP##_*.md`    | 可拍分镜表：shot_id、画面、对白、CHAR/SCENE/形象    |
| **3** | **机器可读** | `EP##_shots.yaml`        | 从分集 md 导出，勿手改 yaml 当源                    |
| **4** | **段落 API** | `EP##_segments.yaml`     | 按 md 镜号合并为 segment；对白与第2步引号内字面一致 |
| **5** | **其它**     | 声音卡片、资产索引等       | 仅在前几步定稿后随需更新                            |

**禁止**先改 `segments.yaml` 再回头补剧本。**单集真相源**是 `剧本/EP##/EP##_*.md`。

## 六、分段规则

### 分段（Segment）规则 —— AI 生成单位

| 约束             | 值              | 说明                                                    |
| ---------------- | --------------- | ------------------------------------------------------- |
| 单 segment 时长  | **4–12 秒**     | Seedance fast 硬限制；超出必须拆分                      |
| 理想时长         | 8–10 秒         | 一条 API = 一段可拍的戏                                 |
| 每 segment 镜头数 | 1–3 镜          | 不超过 3 个镜头                                         |
| 最小叙事单位     | 1 个完整 beat   | 每个 segment 必须构成完整叙事节拍                       |
| 每集段落数       | 12–15 段        | 对应单集 2.5 分钟时长                                   |
| 单集最短时长     | 140 秒          | 约 2 分 20 秒                                           |
| 单集最长时长     | 200 秒          | 约 3 分 20 秒                                           |

### 拆分原则

1. **不得**在对话中间切断 segment（一句台词必须落在同一段内）
2. **不得**在连续动作进行中切断（开门、摘道具等动作链一条 segment）
3. 拆段边界：场景切换、主说话人切换、情绪断点
4. 单段主说话人 ≤ 2；长对手戏拆成 `SEGxxa` / `SEGxxb`
5. 分镜表里某镜自然时长 < 4 秒 → **并入同场景相邻段**

### 关键区分

- **场景（SCENE-###）** = 空间单位（地点不变 = 同一场景）
- **Segment（SEGxx）** = AI 生成单位（一次 Seedance API 调用）
- 同一场景**可以**包含多个 segment；segment **不得**跨场景

### 分集剧本格式规范（11 列镜头表）

分集剧本（`剧本/EP##/EP##_*.md`）使用以下 11 列镜头表：

| 镜号 | shot_id | 场景 | 角色 | 形象 | 景别 | 时长 | 模式 | 运镜 | 画面 | 对白备注 |
|------|---------|------|------|------|------|------|------|------|------|----------|

- SEG 块以 `---` 分隔，每段附 `> ⏱ Segment时长：Xs` 统计行
- 对白格式：`**CHAR-###**[情绪]：「台词」`；无对白写 `（无对白，[音效]）`

## 八、音色规范

### 语音描述格式

每个有对白的角色必须有 `voice_prompt`，格式：
```
「[性别]，[年龄]岁，[音色特征]，[语速]，[情绪基调/说话习惯]」
```

### 旁白与音效

- 旁白角色不分配 CHAR-ID，写为「旁白」，voice_prompt 独立定义
- 分集剧本镜头表中标注音效（如 `敲门声`、`紧张弦乐`）
- Seedance `generate_audio: true` 合成基础环境音；特殊音效后期叠加

### 声音卡片权威来源

- `资产/声音卡片.md` 是 voice_prompt 的 **P0 唯一权威来源**
- segment-builder 必须从此文件**全文复制** voice_prompt 到 YAML
- 同一角色跨 segment 的 `voice_prompt` 必须**全文一致**

## 九、年代/题材约束

### 必须体现元素

- 2020年代中国一线城市（上海为主，第三幕北京）
- 现代都市生活细节：外卖、手机支付、社交媒体、短视频热搜
- 典型的都市白领职场生态：开放式办公、加班文化、商务精英着装
- 公寓合租文化：共享客厅厨房、独立卧室、冰箱便签
- 当代家庭关系：传统大家长制与现代个人选择的冲突

### 禁止出现元素（结构性约束）

- **禁止**：古代物品（古装、兵器、文房四宝、宫灯等不符合2020年代的元素）
- **禁止**：奇幻/玄幻元素（法术、异能、非人类种族、超自然现象）
- **禁止**：与2020年代中国一线城市严重不符的时代错位（如BP机、公用电话亭作为主要通讯方式）
- **禁止**：非现代中国的异域设定（中世纪城堡、日本和室、西方教堂婚礼等——除非剧情明确出国场景）

> 注：以上为结构性年代/题材约束。创意领域 negative_prompt（如「禁止动漫风格」「禁止低质量渲染」等）由 character-designer 和 scene-prop-designer 各自负责。
