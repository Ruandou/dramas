## 二、Top 5 问题（按严重程度排序）

### 🔴 问题 1（高优先）：EP01 剧本 .md 的时长数据自相矛盾

- **位置**：`剧本/EP01/EP01_金像奖之夜.md` L226-248
- **现象**：
  - VALIDATION 块声称 `total_duration: 109s`（L226）
  - 自检对白密度声称"总时长 1.82min = 109s"（L221, L231）
  - 镜头表逐镜时长实际求和 = **6+6+6+6+6+6+6+5+6+6+5+5+5+6+7+6 = 93s**（不是 109s）
  - Segment 时长汇总表（SEG01–SEG10 = 12+12+6+6+11+12+10+11+7+6 = **93s**）—— 与 VALIDATION 块冲突
- **影响**：
  - segment-builder 在 SOURCE FIDELITY PROOF 块中**自行发现**了 16s 差距，并"以自己计算值为准"声明 Gate 仍 PASS
  - 但**剧本文件的 VALIDATION 块是上游真相源**，数据自相矛盾意味着 scene-writer 或后续审计无法可靠引用
  - **真实总时长 = 93s**，落在 G4 下限 75s 之上 — 实际上**仍然合规**，但**文件呈现不一致**
- **建议修复**：
  1. 将 VALIDATION 块的 `total_duration: 109s` 改为 `total_duration: 93s`
  2. 同步修正 L221 / L231 的"1.82min"为"1.55min"
  3. 同步修正 L215 的"≥37（1.82min×20）"为"≥31（1.55min×20）"——并把对白密度 37 行仍满足该修正后的下限
  4. 同步修正 L249 Segment 时长汇总表已为 93s（已是正确值）
- **严重度评估**：不阻断提交，但**违反"上游真相源必须自洽"原则**，影响 R2 报告和 segment-builder 之间的信任链。
