## 一、ID 命名规则

| 类型     | 格式                              | 示例              | 用途                             |
| -------- | --------------------------------- | ----------------- | -------------------------------- |
| **角色** | `CHAR-###`                        | `CHAR-001`        | 对白、关系、选角（谁）           |
| **形象** | `CHAR-###-L##`                    | `CHAR-001-L01`    | 出图、妆造、分镜视觉（长什么样） |
| 群演     | `CHAR-GRP-##` / `CHAR-GRP-##-L01` | `CHAR-GRP-01-L01` | 通用脸型一套即可                 |
| 场景     | `SCENE-###`                       | `SCENE-002`       | 布景                             |
| 分集     | `EP##`                            | `EP01`            | 分集文件                         |
| 道具     | `PROP-###`                        | `PROP-001`        | 口罩、钥匙、手机等              |

- 编号**只增不删**；弃用标 `deprecated: true`。
- 新建角色：先 `资产/角色索引.md`，再建 **`L01` 基础形象**于 `资产/形象索引.md` + `角色卡.md`。
- 新建换装/阶段：**只加 `L02+` 衍生形象**，并写明 `based_on: CHAR-xxx-L01`。

### 1.1 形象 ID 与基础 / 衍生

| 后缀     | 名称     | 要求                                                                                |
| -------- | -------- | ----------------------------------------------------------------------------------- |
| **L01**  | 基础形象 | 完整定妆 Prompt（脸、体型、发式、默认服装）；全剧面部一致性的**唯一锚点**           |
| **L02+** | 衍生形象 | **必须** `based_on` 本角色 `L01`；Prompt 只写差异，并含 `same face as CHAR-xxx-L01` |

**出图流程**：定稿 `L01` 参考图 → 衍生形象用图生图 / 角色一致性模型 → 禁止跳过 L01 直接生成 L02。

**本剧常见衍生场景**：

| 角色 | L01（基础）           | L02+（衍生示例）                               |
| ---- | --------------------- | ---------------------------------------------- |
| 陆见 | 卫衣运动裤（居家）    | L02 白衬衫（见甲方/法院）、L03 干净T恤（求婚） |
| 温宁 | 口罩+帽子（隐藏身份） | L02 摘口罩居家、L03 无遮挡街拍、L04 片场工作装 |
| 沈鹿 | 口罩+墨镜（低调）     | L02 正脸出镜（片场）                           |

## 四、工作流顺序（必读 · 防不同步）

### 4.1 修改顺序

改台词、场次、字幕/旁白策略时**严格按层向下**，**禁止**先改 `segments.yaml` 或 `shots.yaml` 再回头补剧本。

| 顺序  | 层           | 文件                                                                   | 写什么                                                                               |
| :---: | ------------ | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| **1** | **主剧本**   | [`短剧剧本_全楼都觉得我和女明星同居_36集.md`](./短剧剧本_全楼都觉得我和女明星同居_36集.md) | 集纲、每场剧情、对白要点、钩子                                                       |
| **2** | **分集剧本** | [`剧本/EP##/EP##_*.md`](./剧本/)                                       | 可拍分镜表：`shot_id`、画面、**对白/备注**、CHAR/SCENE/形象、时长/模式/运镜          |
| **3** | **机器可读** | 同目录 `EP##_shots.yaml`                                               | 从分集 md 导出，勿手改 yaml 当源                                                     |
| **4** | **段落 API** | 同目录 `EP##_segments.yaml`                                            | 按 md 镜号合并为 segment；`api.text` 对白/字幕/旁白与 **第 2 步引号内字面一致**      |
| **5** | **其它**     | 声音卡、现代视觉规范、assets/                                           | 仅在前几步定稿后随需更新                                                             |

**Agent / 人工自检**（改完第 2 步后）：

- [ ] 主剧本该集对白要点已与分集表一致（或注明「分集为准」并只改分集）
- [ ] 未单独改 `segments` 而 md 未动

**单集真相源**：拍什么、说什么 → **`剧本/EP##/EP##_*.md`**；主剧本为纲，segments 为 API 展开，**不是**编剧起点。

## 五、分集文件头（YAML）

每集文件顶部：

```yaml
---
episode_id: EP01
episode_title: 敲门
duration_min: 2.5
season: S1
scene_ids: [SCENE-001, SCENE-002]
character_ids: [CHAR-001, CHAR-002]
look_ids: [CHAR-001-L01, CHAR-002-L01]
seedance_defaults:
  model: doubao-seedance-2-0-fast-260128
  ratio: "9:16"
  resolution: 720p
  duration_sec: 8-10
  generate_audio: true
  prompt_suffix: "禁止画面中出现任何文字或字幕"
  negative_prompt: "real celebrity face, real brand logo, ancient costume, weapon, military uniform, gun, explosion, anime style, cartoon style"
---
```

**字段说明**：

| 字段                | 说明                                    |
| ------------------- | --------------------------------------- |
| `episode_id`        | `EP##` 格式                             |
| `episode_title`     | 集标题                                  |
| `duration_min`      | 目标时长（分钟），本剧 2–3 分钟         |
| `season`            | 固定 `S1`（全 36 集为第一季）           |
| `scene_ids`         | 本集涉及场景 ID 列表                    |
| `character_ids`     | 本集涉及角色 ID 列表                    |
| `look_ids`          | 本集涉及形象 ID 列表                    |
| `seedance_defaults` | Seedance 生成默认参数                   |

## 七、AI 出图/视频衔接

### 7.1 出图流程

1. 分镜 **`场景`** → `资产/场景卡片.md` → `SCENE-###`
2. 分镜 **`形象`** → `资产/形象索引.md` → `角色卡.md` 内该 **L##** 的 Prompt
3. **L01**：用「基础 Prompt」生成 Character Sheet（正面全身，白底）
4. **L02+**：`based_on` 指向 L01 参考图 + **delta Prompt**（仅服装/场合/妆效）
5. 多角色同框：按形象 ID 顺序合并；每人脸对应其 `L##`，禁止混用别角 L01
6. 分镜 **`角色`** 列仅用于对白表，不参与出图 Prompt 拼接

### 7.2 角色一致性规则

- 每个角色 **L01** 生成后，所有后续出现必须使用该 L01 作为 reference_image
- 衍生形象仅改变服装/状态，面部特征锁定为 L01
- 多人同框时，每人必须挂对应的 `looks/CHAR-*-L##.png`
- **口罩/帽子角色注意**：温宁 L01 有口罩+帽子，L02 摘除时面部仍锁 L01

### 7.3 现代都市合规 Negative Prompt

所有生成任务（图片/视频）**必须**在 negative prompt 中包含 §6.3 模板内容，确保无品牌穿帮与年代穿帮。

### 7.4 场景出图要求

- 每个 `SCENE-*` 必须有对应参考图 `assets/scenes/SCENE-*.png`
- 场景参考图必须符合 §6.1 现代元素
- 注意：室内场景避免出现可识别品牌；屏幕若入画须做模糊处理

### 7.5 引用图片提交策略（TOS 模式）

Seedance 2.0 API 文档标称支持每段最多 9 张引用图片。本项目所有参考图统一通过 TOS 永久图床提交，**每 segment 最多 6 张参考图**。

**TOS 永久图床**：
- 桶名/区域默认：`drama-reference-images` / `cn-beijing`
- URL 格式：`https://{bucket}.tos-cn-beijing.volces.com/{prefix}/{filename}`
- 上传工具：`mcps/volc-ark/scripts/tos_upload.py sync --project-root .`
- 上传后在 `cdn_urls.json` 的 `tos_url` 字段存储永久链接

**实施要求**：
- 上传图片至 TOS 后，在 `assets/looks/` 或 `assets/scenes/` 同目录下维护 `cdn_urls.json`：
  ```json
  {
    "CHAR-001-L01": {
      "local": "CHAR-001-L01.png",
      "tos_url": "https://drama-reference-images.tos-cn-beijing.volces.com/looks/CHAR-001-L01.png"
    }
  }
  ```
- 提交脚本读取 `tos_url` 作为 reference_image
- **每 segment 最多 6 张参考图**（多角色 + 场景 + 道具组合需在此上限内规划）
- 本地 PNG 文件始终保留作为最终备份

### 7.6 资产粒度与 API 配额分配规则

#### 资产粒度判定标准

**角色粒度**：

| 条件 | 处理方式 |
|------|----------|
| 有名字 + 有台词 + 跨segment出现 | 独立 `CHAR-###` + 独立参考图 |
| 有名字 + 有台词 + 仅单次出镜 | 视情况：若后续集会复现 → 独立ID；否则可留 `CHAR-GRP` |
| 有台词但匿名（如"狗仔甲"） | 保持 `CHAR-GRP`，用子角色标注 `CHAR-GRP-##(角色)` |
| 纯背景无台词 | 保持 `CHAR-GRP`，无需单独参考图 |
| 纯语音无画面（电话声等） | 保持 `CHAR-GRP`，无需参考图 |

**场景粒度**：

| 条件 | 处理方式 |
|------|----------|
| 同一物理空间 + 同一视觉风格 | 共用一个 `SCENE-###` |
| 同一物理空间 + 视角/区域差异大（如客厅 vs 阳台） | 拆分为不同 `SCENE-###` |
| 不同物理空间 | 必须不同 `SCENE-###` |

**道具粒度**：

| 条件 | 处理方式 |
|------|----------|
| 多个segment重复出现 + 需要外观一致 | 独立 `PROP-###` + 外观描述 + 可选参考图 |
| 需后期合成文字的道具 | 必须独立 `PROP-###`（便于后期脚本引用） |
| 仅单镜一次性出现 | 在画面描写中描述即可，不需独立编号 |

#### API 配额分配优先级

每个 segment 的参考图数量上限为 **6 张（TOS 模式）**。当配额不足时，按以下优先级分配：

| 优先级 | 资产类型 | 说明 |
|--------|---------|------|
| P0 | 主角形象 | 必须保证，否则换脸 |
| P1 | 对手/对话角色形象 | 有互动的角色必须锁定 |
| P2 | 场景参考图 | 保证环境一致性 |
| P3 | 关键道具参考图 | 有余量时加入，否则靠prompt描述兜底 |
| P4 | 次要角色/群演 | 最后考虑，必要时用通用群演图 |

#### 配额计算示例

典型双人对话 segment（陆见+温宁客厅对话）：
- 陆见形象 × 1
- 温宁形象 × 1  
- 场景参考 × 1
- 关键道具 × 1（如有）
- **合计 3-4 张** ✅ 在安全范围内

三人+道具 segment（陆见+温宁+林大妈楼道）：
- 陆见 × 1 + 温宁 × 1 + 林大妈 × 1
- 场景 × 1
- 道具 × 1
- **合计 5 张** ✅ 在 6 张上限内

#### 自检规则

拍摄脚本完成后，逐 segment 检查参考图需求：
1. 统计每 segment 涉及的独立角色数 + 场景 + 道具
2. 若总数 > 6 → 必须拆分 segment 或按 P0–P4 优先级降低道具/次要角色

## 八、道具转移与肢体动作（防错清单）

适用：开门、摘口罩、递钥匙、拉住手臂、推人等 **「谁碰什么」** 明确的镜。

### 8.1 常见模型错误

| 现象           | 原因                                                                       |
| -------------- | -------------------------------------------------------------------------- |
| 道具尺度漂移   | 口罩忽大忽小；钥匙串形状变化；prompt 写「口罩」无具体描述                 |
| 配角先动手     | 上一镜陆见对白，下一镜「开门/递钥匙」未绑 **图N 陆见**                     |
| 段内跳切不连贯 | prompt 写成镜头清单，各镜各画，不保证同一件道具、同一人持有               |
| 表情与台词不符 | 画面描述与对白情绪未对齐（如台词是紧张，画面描述却是「自信微笑」）        |

### 8.2 分段原则（先于 prompt）

- **同一场戏、同一道具动作链** → **一条 segment**，勿拆成多条 API 任务。
- 对白镜与动作镜在同一 segment 时：**对白者 ≠ 动作者** 必须写清绑定。
- 单段 **≤1 句对白**；复杂情绪段尽量少人同框。

### 8.3 `api.text` 写法（强制）

1. **段首「角色分工」**：谁可接触道具、谁**禁止**（例：仅图1 陆见开门；图2 温宁双手不得碰门把）。
2. **每镜绑 `图N` + 服装色**：用 `图1`/`图2`，不用泛称「男主」「邻居」；`content_roles` 顺序与全文一致。
3. **道具锁定**：具体描述（白色KN95口罩，标准成人尺寸）；禁止堆叠模糊修饰词。
4. **因果链叙事**，非 Excel 清单：  
   `图1 打开门探头 → 图2 侧身站在门外 → 图1 愣住后退半步 → 图2 低头避开目光`
5. **关键镜重复约束**：开门、摘口罩镜再写一次「图1 手在门把 / 图2 口罩遮面」。

## 九、有声段落（Seedance 2.0 · 默认）

1. **提交单位**：`EP##_segments.yaml` 中每条 `segment_id`（约 8–12 秒），非一镜一任务。
2. **音频**：`generate_audio: true`；对白与 **voice_prompt** 写在 `api.text`。
3. **画面**：段落仅用 `looks/` + `scenes/`；不依赖镜级首帧。
4. **一段一落音**：单段主说话人 ≤2；长对手戏拆成 `SEGxxa` / `SEGxxb`。
5. **音色文案**：同一角色跨段 **voice_prompt 全文一致**。  
   - 陆见：「成年男性，27岁，语调平缓偏低沉，带有轻微社恐感，语速偏慢，说话时常停顿」  
   - 温宁：「成年女性，25岁，声线清冷但柔和，防备时语速快且压低，放松时温暖自然」  
   - 文姐：「成年女性，38岁，声线尖利有控制力，语速快，带有压迫感和威胁性」  
   5.1 **字幕（默认全段）**：后期通过 ffmpeg 统一添加，Seedance 不烧录字幕。  
   5.2 **字卡镜**：并入相邻段，画面字幕一字不差，无旁白念稿。
6. **验收**：全段耳听+目视字幕是否与引号一致。
7. **成片**：`assets/generated/EP##/` 下 `EP##-SEG*.mp4`；集级 `script/ffmpeg_concat_episode.sh`。
8. **段落时长（API）**：`duration_sec` 对 **fast** 只能 **4–12**（硬限制）。
9. **合理分段（制片）**：
   - **一条 API = 一段可拍的戏（约 4–12 秒信息密度）**，不是「一镜一条」。
   - 分镜表里某镜自然时长 **< 4 秒**：**并入同场景相邻段**，不要单独开段。
   - 拆段边界：场切换、主说话人切换、情绪断点；不要按 `shot_id` 机械切。

### 9.1 Segment 拆分规则（强制）

> 防止 segment 超长导致 AI 无法生成。任何分镜表 / `EP##_segments.yaml` 编写阶段都必须遵守。

| 约束             | 值              | 说明                                                                |
| ---------------- | --------------- | ------------------------------------------------------------------- |
| 单 segment 时长  | **4–12 秒**     | 超过 12 秒的 segment 无法被 Seedance 生成，**必须**拆分             |
| 理想时长         | 8–10 秒         | 与本剧 `seedance_defaults.duration_sec: 8-10` 一致                  |
| 每 segment 镜头数 | 1–3 镜          | 不超过 3 个镜头                                                     |
| 最小叙事单位     | 1 个完整 beat   | 每个 segment 必须构成完整叙事节拍（有动作起止、有情绪弧）           |

**关键区分（务必分清）**：

- **场景（SCENE-###）** = **空间单位**（地点不变 = 同一场景）；与道具协议 §8、视觉规范 §6 绑定。
- **Segment（SEGxx / SEGxxa-b）** = **AI 生成单位**（一次 Seedance API 调用），与 §9 时长硬限制绑定。
- 同一场景**可以**包含多个 segment；segment **不得**跨场景（场切即断段，见 §9 第 9 条「拆段边界」）。

**拆分原则**：

1. **不得**在对话中间切断 segment（一句台词必须落在同一段内）。
2. **不得**在连续动作进行中切断 segment（如开门、摘口罩、拉手未完成）。
3. 每个 segment 结束时应有自然停顿点（台词说完、动作完成、表情定格），便于后期拼接与字幕对齐。
4. 相邻 segment 之间允许轻微画面跳接（时间/角度微变），但不应有逻辑断裂；跨段的道具持有人参考 §8.3 第 5 条「关键镜重复约束」。

**分集剧本（`剧本/EP##/EP##_*.md`）中的标注要求**：

- 每个 SEG 后标注：`> ⏱ Segment时长：Xs ｜ 镜头数：N`（X ∈ [4, 12]）。
- 同场景续接段使用 `**（续）**` 标记，**不重复**写场景头（SCENE / 时间 / 地点）。
- `EP##_segments.yaml` 中 `duration_sec` 必须落在 **4–12** 区间，超出即视为违规，必须回到第 2 步分集 md 重新拆段。

**自检清单（提交 `EP##_segments.yaml` 前）**：

- [ ] 所有 segment 的 `duration_sec` 是否都在 4–12？
- [ ] 是否存在跨场景的 segment？（必须断段）
- [ ] 是否存在切断对白或连续动作的拆点？
- [ ] 单 segment 内主说话人是否 ≤ 2，镜头数是否 ≤ 3？

### 9.10 Seedance 段落 Prompt 结构规范

为避免双字幕和字幕不一致，每段 `api.text` 必须遵循以下结构：

```
【图1】角色 ID【图2】场景 ID。
竖屏9比16连贯叙事。
镜头1（Xs）[景别][运镜]：[纯视觉动作描述，不含对白]
镜头2（Xs）[景别][运镜]：[纯视觉动作描述，不含对白]
[以下对白仅供语音合成，严禁在画面中显示任何文字]
对白（角色A，年龄，情绪）：「台词」
对白（角色B，年龄，情绪）：「台词」
画面全程无任何文字、字幕、标题、水印。
现代中国都市住宅小区，写实都市剧风格，竖屏9比16，无品牌 Logo，无平台 UI，无历史道具。
[negative_prompt]
[prompt_suffix]
```

**禁止事项：**
1. **禁止**在镜头描述中嵌入对白文字（会导致双字幕）
2. **禁止**在段落级添加 `字幕：...` 指令（全局 `prompt_suffix` 已包含统一字幕规则）
3. **禁止**在多处重复出现相同对白文字

**字幕统一由 `prompt_suffix` 控制：**
`"禁止画面中出现任何文字或字幕"`

### §9.11 字幕策略：后期添加

字幕**不由 Seedance 烧录**，改为后期通过 ffmpeg 统一添加。

- `prompt_suffix`: `"禁止画面中出现任何文字或字幕"`
- `prompt_suffix_silent`: `"本段无对白无语音，禁止画面中出现任何文字"`
- 对白文本保留在 prompt 中用于语音合成（`generate_audio: true`）
- 字幕样式（字体、字号、颜色、位置）在后期统一控制

#### §9.11.2 后期字幕流水线（Whisper + 校对 + 烧录）

整集拼接完成后，字幕**必须听写成片音频**，禁止用 `segments.yaml` 对白按时长比例估时。

**三步（Agent 须自动执行，含第 2 步校对）：**

```bash
cd dramas/全楼都觉得我和女明星同居

# 1. 听写
HF_ENDPOINT=https://hf-mirror.com python3 script/gen_audio_srt.py \
  assets/generated/EP##/EP##_full.mp4 \
  -o assets/generated/EP##/EP##_audio.srt

# 2. 校对（对照 segments.yaml dialogue_lines，修同音错字；保留 Whisper 时间轴）
python3 script/review_audio_srt.py assets/generated/EP##/EP##_audio.srt

# 3. 烧硬字幕（Pillow + ffmpeg overlay，样式：白字描边、无黑底条）
python3 script/burn_subs_pillow.py \
  assets/generated/EP##/EP##_full.mp4 \
  assets/generated/EP##/EP##_audio.srt \
  -o assets/generated/EP##/EP##_subtitled.mp4
```

**Agent 校对要求（第 2 步后主动执行）：**

- 对照 `剧本/EP##/EP##_segments.yaml` 的 `dialogue_lines`
- **只修明显问题**：同音错字、专有名词（陆见、温宁、沈鹿、文姐、林大妈等）
- **禁止**把短听写句整段替换成剧本长句（会破坏口型/时长）

### §9.12 道具文字后期合成规则

AI视频生成引擎无法可靠渲染中文字符。画面中需要出现的道具文字（手机屏幕、快递单、合同、门牌号等）需遵循以下流程：

1. **拍摄脚本标注**：在画面描写中保留叙事信息（让读者/导演知道观众应该看到什么内容），并加粗标注 **(文字后期合成)**
2. **AI Prompt 生成时**：自动去除具体中文字内容，仅描述物理载体（如"手机亮屏"而非"手机显示微信消息"）
3. **后期处理**：使用 `script/overlay_diegetic_text.py`（或 FFmpeg drawtext）在生成视频上叠加文字
4. **可跳过的情况**：
   - 全景/远景中文字极小、观众看不清 → 不需要叠加
   - 画面描写已标注"微虚处理" → 屏幕内容模糊化处理即可，靠对白交代

**标注格式示例**：

> 手机屏幕亮起 **(屏幕文字"温宁：我到楼下了"后期合成)**

**与其他规则的关系**：

- 与 §6.2（禁止出现）不冲突：AI 生成阶段仍需在 `negative_prompt` 中保留"无品牌 logo、无字幕烧入画面"；道具文字仅在后期叠加。
- 与 §9.10 Prompt 结构不冲突：镜头描述中仅保留物理载体描述，不嵌入中文字面。
- 与 §9.11 字幕策略分工：§9.11 为对白字幕（whisper 听写 + 烘入）；§9.12 为画内道具文字（手动定位叠加）。
