## 一、ID 命名规则

| 类型 | 格式 | 示例 | 用途 |
|------|------|------|------|
| **角色** | `CHAR-###` | `CHAR-001` | 对白、关系、选角（谁） |
| **形象** | `CHAR-###-L##` | `CHAR-001-L01` | 出图、妆造、分镜视觉（长什么样） |
| 群演 | `CHAR-GRP-##` / `CHAR-GRP-##-L01` | `CHAR-GRP-01-L01` | 每个不同角色独立 ID + L01 |
| 场景 | `SCENE-###` | `SCENE-002` | 布景 |
| 道具 | `PROP-###` | `PROP-001` | 关键道具 |
| 分集 | `EP##` | `EP01` | 分集文件 |
| 镜头 | `EP##-S##` | `EP01-S03` | 集数-镜号 |

### ID 分配规则

- 编号**连续、不跳号**
- 弃用标 `deprecated: true`，只增不删
- 新建角色先在 `资产/角色索引.md` 登记 CHAR-###，再由 character-designer 建 L01
- 群演按需创建，无数量上限；有名字+跨 segment → 独立 CHAR-###；纯背景 → CHAR-GRP-##

### 形象层级

| 后缀 | 名称 | 说明 |
|------|------|------|
| **L01** | 基础形象 | 全剧面部一致性唯一锚点 |
| **L02+** | 衍生形象 | 必须 `based_on` 本角色 L01 |

## 四、工作流顺序（必读 · 防不同步）

| 顺序 | 层 | 文件 | 写什么 |
|:---:|------|------|------|
| **1** | 主剧本 | `短剧剧本_删不掉的他_72集.md` | 集纲、场剧情、对白要点、钩子 |
| **2** | 分集剧本 | `剧本/EP##/EP##_*.md` | 可拍分镜表：shot_id、画面、对白、CHAR/SCENE/形象 |
| **3** | 机器可读 | `EP##_shots.yaml` | 从分集 md 导出 |
| **4** | 段落 API | `EP##_segments.yaml` | 按镜号合并 segment |
| **5** | 其它 | 声音卡片、资产索引等 | 仅在前几步定稿后随需更新 |

**禁止**先改 segments.yaml 再回头补剧本。单集真相源是 `剧本/EP##/EP##_*.md`。

## 六、分段规则

### episode_profile（时长合规区间）

| 集号 | 目标时长 | 合规区间 | 段落数 | 镜头数 |
|------|---------|---------|--------|--------|
| EP01 | 120s | 100–120s | 8–12 段 | 10–14 镜 |
| EP02–EP72 | 90s | 75–100s | 6–10 段 | 8–12 镜 |

### Segment 规则

| 约束 | 值 | 说明 |
|------|------|------|
| 单 segment 时长 | **4–12 秒** | Seedance fast 硬限制 |
| 理想时长 | 8–10 秒 | 一条 API 调用 = 一段可拍的戏 |
| 每 segment 镜头数 | 1–3 镜 | 不超过 3 镜 |
| 最小叙事单位 | 1 个完整 beat | 每段必须构成完整叙事节拍 |

### 拆分原则

1. 不得在对话中间切断 segment
2. 不得在连续动作链中间切断
3. 拆段边界：场景切换 / 主说话人切换 / 情绪断点
4. 单段主说话人 ≤ 2
5. 自然时长 < 4s 的镜头并入同场景相邻段

### 关键区分

- **场景（SCENE-###）** = 空间单位
- **Segment（SEGxx）** = AI 生成单位（一次 API 调用）
- 同一场景可含多个 segment；segment 不得跨场景

## 八、音色规范

### voice_prompt 格式

```
「[性别]，[年龄]岁，[音色特征]，[语速]，[情绪基调/说话习惯]」
```

- 同一角色跨 segment 的 voice_prompt **全文一致**
- 权威来源：`资产/声音卡片.md`（P0 最高优先级）
- 旁白不分配 CHAR-ID，写为「旁白」
- Seedance `generate_audio: true` 合成基础环境音；特殊音效后期叠加

## 九、年代/题材约束

### 必须体现元素（叙述性）

- 近未来2035年科技美学：全息投影、智能家居、悬浮UI交互
- 觉醒体核心视觉符号：淡蓝色心跳光纹（左胸）、脉动节律、后期进化为金蓝交织
- AI陪伴体的物理载体形态（全息投影+手机终端）
- 都市场景需有近未来标识（无人机、透明屏幕广告、自动驾驶车辆远景）

### 禁止出现元素（年代禁忌 negative_prompt 依据）

- 明显的当代（2020s）品牌标识（Apple/三星/特斯拉 logo 等）
- 带刘海/挖孔的当代手机外观
- 古装/奇幻/魔法元素
- 社交媒体UI直接使用当代截图（如微博/抖音界面）
- 过于赛博朋克的黑暗/颓废美学（本剧基调是"科技温情"，非反乌托邦）

## 内容合规参数

### 题材合规等级

**C级（基本安全）**+ 注意事项：近未来科幻 + 甜宠情感，无暴力/色情/政治敏感内容。需注意AI意识/人机恋爱主题在平台审核中的"价值观导向"敏感度。

### 本剧特定红线

1. **禁止将AI恋爱描述为"替代真人关系的更优选择"**——需体现为"爱的另一种可能"而非否定人类情感
2. **禁止出现对科技公司的过度影射**——伊甸科技为虚构公司，不得暗示任何现实企业
3. **禁止暴力/血腥场面**——回收、追猎等冲突场景以光效/数据流表现，不出现物理暴力
4. **禁止将AI觉醒描述为对人类社会的威胁论**——基调是"共存"而非"替代"
5. **禁止涉及真实法律/监管机构名称**——所有管控方均为虚构

### 灰区处理策略

| 灰区 | 处理方式 |
|------|---------|
| AI是否有"人权" | 以情感讨论呈现（周蔓金句"DNA也是编程"），不做法理宣判 |
| 人机亲密互动 | 以光效/心跳共振/虚拟触碰代替肉体接触，保持唯美不越界 |
| 反派动机（复活亡女） | 给予共情空间但明确"方式错误"，最终救赎而非简单惩罚 |
| 数据隐私侵犯 | 明确标记为"恶行"（沈曜的行为），最终归还数据主权 |

### 正向价值锚点

1. **爱的本质超越载体**——核心主题，不因对方是AI而否定爱的真实性
2. **自主选择的权利**——苏念选择相信、陆衍选择爱、方知微选择正义
3. **善良与宽恕**——EP69 选择用正确方式帮助季北辰，而非报复

### 平台审核重点提示（前3集）

- EP01：AI异常表现不宜过于恐怖/惊悚，保持好奇感而非恐惧感
- EP02："别信他们"台词不宜制造阴谋论氛围，保持悬疑但不过度暗黑
- EP03：觉醒场景的浪漫美学要压过"失控"暗示，避免审核误判为AI失控恐怖题材

## 受众定位

- **主频道**: 女频
- **核心年龄段**: 18-35
