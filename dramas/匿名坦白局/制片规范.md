## 一、ID 命名规则

所有资产必须使用统一编码，**只增不删**；弃用标 `deprecated: true`。

| 类型     | 格式                              | 示例              | 用途                             |
| -------- | --------------------------------- | ----------------- | -------------------------------- |
| **角色** | `CHAR-###`                        | `CHAR-001`        | 对白、关系、选角（谁）           |
| **形象** | `CHAR-###-L##`                    | `CHAR-001-L01`    | 出图、妆造、分镜视觉（长什么样） |
| 群演     | `CHAR-GRP-##` / `CHAR-GRP-##-L01` | `CHAR-GRP-01-L01` | 通用脸型一套即可                 |
| 场景     | `SCENE-###`                       | `SCENE-002`       | 布景                             |
| 道具     | `PROP-###`                        | `PROP-001`        | 关键道具                         |
| 分集     | `EP##`                            | `EP01`            | 分集文件                         |
| 镜头     | `EP##-S##`                        | `EP01-S03`        | 集数-镜号                        |

### ID 分配规则

- 编号**连续、不跳号**
- 新建角色：先在 `资产/角色索引.md` 登记 `CHAR-###`，再由 character-designer（Stage 3b）建 `L01` 基础形象
- 新建换装/阶段形象：**只加 `L02+` 衍生形象**，并写明 `based_on: CHAR-xxx-L01`
- 群演分级：有名字+跨 segment 出现 → 独立 CHAR-###；纯背景无台词 → CHAR-GRP

### 形象层级结构定义

| 后缀     | 名称     | 说明                                           |
| -------- | -------- | ---------------------------------------------- |
| **L01**  | 基础形象 | 全剧面部一致性的**唯一锚点**                   |
| **L02+** | 衍生形象 | 必须 `based_on` 本角色 `L01`；禁止跳过 L01    |

## 四、工作流顺序（必读 · 防不同步）

| 顺序  | 层           | 文件                     | 写什么                                              |
| :---: | ------------ | ------------------------ | --------------------------------------------------- |
| **1** | **主剧本**   | `短剧剧本_匿名坦白局_72集.md` | 集纲、每场剧情、对白要点、钩子                      |
| **2** | **分集剧本** | `剧本/EP##/EP##_*.md`    | 可拍分镜表：shot_id、画面、对白、CHAR/SCENE/形象    |
| **3** | **机器可读** | `EP##_shots.yaml`        | 从分集 md 导出，勿手改 yaml 当源                    |
| **4** | **段落 API** | `EP##_segments.yaml`     | 按 md 镜号合并为 segment；对白与第2步引号内字面一致 |
| **5** | **其它**     | 声音卡片、资产索引等       | 仅在前几步定稿后随需更新                            |

**禁止**先改 `segments.yaml` 再回头补剧本。**单集真相源**是 `剧本/EP##/EP##_*.md`。

## 六、分段规则

### 分段（Segment）规则 —— AI 生成单位

| 约束             | 值              | 说明                                                    |
| ---------------- | --------------- | ------------------------------------------------------- |
| 单 segment 时长  | **4–12 秒**     | Seedance fast 硬限制；超出必须拆分                      |
| 理想时长         | 8–10 秒         | 一条 API = 一段可拍的戏                                 |
| 每 segment 镜头数 | 1–3 镜          | 不超过 3 个镜头                                         |
| 最小叙事单位     | 1 个完整 beat   | 每个 segment 必须构成完整叙事节拍                       |
| 每集段落数       | 6–12 段（EP01） / 6–10 段（EP02+） | 对应单集时长 |
| 每集镜头数       | 10–14 镜（EP01） / 8–12 镜（EP02+） | 对应每集 6–12 段 × 1–3 镜/段 |

### 拆分原则

1. **不得**在对话中间切断 segment（一句台词必须落在同一段内）
2. **不得**在连续动作进行中切断（开门、摘道具等动作链一条 segment）
3. 拆段边界：场景切换、主说话人切换、情绪断点
4. 单段主说话人 ≤ 2；长对手戏拆成 `SEGxxa` / `SEGxxb`
5. 分镜表里某镜自然时长 < 4 秒 → **并入同场景相邻段**

### 关键区分

- **场景（SCENE-###）** = 空间单位（地点不变 = 同一场景）
- **Segment（SEGxx）** = AI 生成单位（一次 Seedance API 调用）
- 同一场景**可以**包含多个 segment；segment **不得**跨场景

## 九、年代/题材约束

### 年代
近未来（2027-2028年），中国都市。科技适度前瞻但不过度科幻：
- 智能手机、笔记本电脑、社交App为日常配置
- App的"预测"功能以AI数据分析为叙事逻辑基础，**无超自然元素**
- 服务器/代码/加密等技术设定需保持基本合理性

### 必须体现元素
- 都市日常质感：出租屋、医院、办公室、便利店、天台
- AI与人性对照：App冷色调 vs 人类情感暖色调
- 道德灰色地带：每一集都是人性的镜子，没有绝对的善恶
- 声音/倾听的力量（后半程核心主题）

### 禁止出现元素（叙述性 — Prompt 细节由设计师负责）
- 超自然现象、灵异、鬼怪
- 暴力美学、血腥画面
- 政治隐喻、司法/政府系统批评
- 色情内容、低俗台词
- 封建迷信言论
- 对AI的全面否定或全面崇拜（需保持辩证立场）

## 十一、内容合规参数

### 题材合规等级
🟢 **C级** — 都市心理悬疑 / 社会寓言。不涉及刑侦/法庭/军事/政治/封建迷信。无超自然元素。

### 本剧特定红线
1. **"法律无法定罪"表述**（EP47）：需改写为"现有法律对AI行为缺乏明确界定"，避免暗示法律无能。强调法律在完善中。
2. **AI制造秘密/伪造证据**（EP45-46）：需明确标注AI行为是"预期之外"的技术失控，而非苏晴主观恶意犯罪。AI行为不代表对司法制度的影射。
3. **集体投票猎巫场景**（EP20-21）：避免呈现群体暴力/网络暴力被美化为正义。需通过角色台词传达"多数人暴政"的批判立场。
4. **自杀相关情节**（EP09周远妹妹、EP19诬陷者）：不带画面呈现自杀行为本身。只以对话/文字提及，且需立即转向正向价值（EP39揭示妹妹未死）。
5. **废弃工厂对峙**（EP54-55）：避免呈现真实暴力。对峙靠台词张力而非肢体冲突驱动。

### 灰区处理策略
| 灰区 | 出现集数 | 处理策略 |
|------|---------|----------|
| AI伪造秘密导致他人受害 | EP45–46 | 明确AI行为为"技术失控"，苏晴承担道德责任但非主观犯罪。EP49–51 安排逐一道歉补偿。 |
| 公众投票决定他人秘密公开 | EP20–21 | 通过林小果的视角批判，用EP24主动坦白和EP30民主化投票反转，将"被动审判"转为"主动坦白"。 |
| 苏晴修改父亲AI模型参数 | EP32 | 呈现为疏忽而非恶意，EP59 通过父亲留言闭环——父亲早已知道并原谅。 |
| 周远默许妹妹测试并欠高利贷 | EP43 | 立即安排周雨耳光+周远下跪道歉，不让道德瑕疵悬置。 |

### 正向价值锚点
1. **坦白然后原谅**（核心金句，全剧精神内核）：面对真相的勇气 + 原谅自己与他人的智慧
2. **倾听的力量**（EP66–72）：从"投递秘密"到"倾听秘密"的价值升级——人类连接比技术审判更有力量
3. **反思而非审判**：App的"坦白局"最终进化成"原谅局"，传递"了解真相是为了理解而非惩罚"

### 平台审核重点提示（前三集）
- **EP01**：5000元到账场景 — 确保不传递"通过不当手段轻松获利"的信号；需通过林小果的犹豫和母亲的病情强调"被逼无奈"
- **EP02**：婴儿母亲崩溃场景 — 不呈现婴儿哭喊的惨烈画面；聚焦林小果的愧疚反应而非受害者痛苦
- **EP03**：老吴被带走调查 — 避免呈现执法场景；通过办公室议论间接传达

## 十七、数据权威性声明（Canonical Source Authority）

### voice_prompt 权威来源

| 优先级 | 文件 | 说明 |
|--------|------|------|
| **P0（最高）** | `资产/声音卡片.md` | 专门定义声音参数的文件，最细粒度、最权威 |
| P1 | `资产/角色卡片.md` | 角色总览中的 voice_prompt 字段 |
| P2（兜底） | `制片规范.md` | 本文件音色规范章节 |

**规则**：存在 P0 时，**一律使用 P0**，忽略 P1/P2 中的 voice_prompt。voice_prompt 必须**全文复制**（含「」内全部文字），禁止缩写、改写、翻译、简化。

### 角色数据权威来源

| 数据类型 | 权威来源 | 说明 |
|----------|----------|------|
| 角色 ID（CHAR-###） | `资产/角色索引.md` | 唯一定义；character-designer 不可自行新增 |
| 形象 ID（CHAR-###-L##） | `资产/角色卡片.md` / `资产/形象索引.md` | 角色卡片定义，形象索引补充 |
| 场景 ID（SCENE-###） | `资产/场景卡片.md` | 唯一定义 |
| 道具 ID（PROP-###） | `资产/道具卡片.md` | 唯一定义 |
| voice_prompt | `资产/声音卡片.md`（见上表） | 最高优先 |

### 双通道移交协议

- **production-planner → character-designer**：角色卡片骨架（ID + 身份元数据 + 语言画像）+ 形象索引骨架
- **production-planner → prop-designer**：道具卡片（ID + 持有者 + 关联场景 + 叙事功能）
- **production-planner → scene-designer**：场景卡片（ID + 地点 + 氛围 + 叙事重要性）
- **不可修改**：ID 编号、表格格式、必填元数据字段
