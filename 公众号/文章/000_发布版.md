先说现象：我第一次把角色参考图塞进视频生成接口，提交的那一集，段段被拒。返回的不是排队状态，是一行错误码：

- `HTTP 400 BadRequest`
- `InputImageSensitiveContentDetected.PrivacyInformation`
- `"输入图片可能包含真人，请您更换后重试。"`

不建单、不扣费，听起来挺友好。实际后果是整集停摆：那批参考图是 23 张角色形象图，每张 ¥0.72；视频段一段也开不了工。

## 拦我的是哪条策略

Seedance 2.0 在**输入侧**加了人脸审核，官方风控文档里「审核位置」那一栏写的是「输入图片、视频」。

只要参考图里有照片级写实的人脸，就按「疑似真人」处理——它不区分这张脸是相机拍的还是模型画的。

我做的全是虚构角色，脸是图片生成模型画出来的。所以这不是拿真人肖像去生成内容，是**误伤**。

## 三条走不通的路

- **① 在提示词里声明「这是虚拟角色」**：没用。风控不看文字，只看图。
- **② 把角色画得不像真人**（更卡通、更概念画）：能过，但整部剧的视觉风格跟着废了。为过审牺牲风格是本末倒置。
- **③ 轻度 CG 风格化重渲染**（把照片渲染成 3D 动画质感）：实测**仍然被拒**。这条我试过，别浪费时间。

## 走通的这条：给脸戴一张三角网格

做法一句话：**在原图的面部区域叠一层 AR 滤镜风格的三角网格，然后用这张「戴面具」的图去提交视频生成。**

提交通过。而且——这是关键——网格不会出现在成片里，脸也没崩。

**原理我不知道，只说清我知道的**：我验证到的只是相关性（叠网格 → 通过；不叠 → 拒），没验证因果。我的猜测是风控把「脸上覆盖规则三角网」识别成 3D / 合成资产的特征，而不是真人照片的生物特征。这条属于黑盒推断，别当结论用。

## 具体三步

- **① 定位面部**（用 macOS 自带 Vision，不联网、不装模型）：`python3 script/detect_face_rect.py assets/looks/CHAR-001-L01.png`，输出 `791,418,204,240` ← cx,cy,rx,ry，面部椭圆的像素坐标
- **② 叠网格**：`python3 script/add_face_mesh.py --input assets/looks/CHAR-001-L01.png --output assets/looks/CHAR-001-L01-mesh.png --face 791,418,204,240`
- **③ 上传对象存储**，提交视频时用 `-mesh` 版那张：`python3 mcps/volc-ark/scripts/tos_upload.py sync --project-root dramas/剧名目录`

网格参数：9 行 × 7 列节点，每个节点随机抖动 ±6px，青色网格线宽 3px，节点圆点半径 4px，随机种子固定为 7（同一张图重跑结果一致，可复现）。

整条链路是本地 Pillow 画图：**零 API 调用、零扣费**，一张图两秒。

## 两个反直觉的结果

**一，网格不会被复现进成片。** 我最初担心的是完全相反的事：参考图上的网格会不会长到角色脸上，做出一部「脸上带网格」的剧。2026-07-26 第一次全量验证——《满级师尊她装作刚入门》EP01，10 段全部出片，男女角色、特写和全景都查过，成片里没有网格。

**二，戴了面具，脸没崩。** 这才是这个方案能用的前提。参考图的唯一职责就是锁脸：如果叠完网格模型认不出同一张脸，那等于白折腾，还白扣一次费。实测 mesh 版与原图在面部一致性上没有可辨差异。

## 四条边界，不写清就会踩

- **① mesh 版只喂给视频生成**。图片生成侧做角色衍生形象（换装、受伤、大婚）时，参考图仍然传**原图**，不是 mesh 版——两条链路，两种用法。
- **② 逆光剪影、背影、面容隐没的角色豁免**，不生成 mesh。但豁免原因必须登记到形象索引表里，否则下游会当成缺口重做一遍（重复扣费）。
- **③ 群演同样适用**。别觉得小角色可以糊过去，每个有正脸的群演都要一张 mesh 版。
- **④ 坐标必须目检**。自动检测返回的是「最大那张脸」的椭圆，侧脸、遮挡、多人同框时不一定盖得住——画歪了等于没画。

## 这算不算绕过平台风控

值得单独说一句。这条策略的目标是防止**真人肖像**被拿去生成内容；我的输入是模型画的虚构角色，落在误伤范围内。叠网格不会让任何一张真人照片通过审核。

**根治办法是官方的 AIGC 白名单**，我在并行申请。白名单下来之后这层面具就该退场——它是等待期里让一部剧能开工的工程手段，不是长期方案。

顺带一个提醒：输入侧过了，**输出侧还是可能被拦**。官方 FAQ 里有一条解释是模型推理过程中可能「自我发挥，拟合到明星脸」。所以这层面具解决的是「我的参考图是不是像真人」，不解决「模型自己画出了某个明星」。
